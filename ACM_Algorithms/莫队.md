# 莫队简介
## 定义
莫队算法是解决对于长度为$n$的序列上的区间询问问题，如果从 $[l,r]$ 的答案能够 $O(1)$ 扩展到 $[l-1,r],[l+1,r],[l,r+1],[l,r-1]$（即与 $[l,r]$ 相邻的区间）的答案，那么可以在 $O(n\sqrt{n})$ 的复杂度内求出所有询问的答案。倘若是朴素算法，那么时间复杂度应为$O(nq)$。
相对于线段树这类处理$RMQ$问题的数据结构来说，莫队主要处理线段树这类数据结构无法处理的问题。

那么其实莫队算法是一种优雅的暴力算法，本质上的操作就是对所有询问进行排序，然后从小到大依次处理所有的询问。所以，普通的莫队算法是一种**离线**算法。
## 例
给一个简单的例子[P1494 [国家集训队] 小 Z 的袜子 - 洛谷](https://www.luogu.com.cn/problem/P1494)。
题目大意：有一个长度为 $n$ 的序列 $\{c_i\}$。现在给出 $m$ 个询问，每次给出两个数 $l,r$，从编号在 $l$ 到 $r$ 之间的数中随机选出两个不同的数，求两个数相等的概率。

那么对于这种多次区间查询，一般来说，我们都会想到线段树、树状数组等等数据结构，但是如果这道题使用线段树，那么只能算出一种颜色的概率，倘若要查询多种颜色，必然会再多一个$O(n)$的时间，这是无法接受的。所以这道题只能用莫队解决。
### 解
那么在给出莫队操作之前，先看看这题如何解决。
要我们求区间取出两个相同数字的概率。那么我们可以直接列出式子
$$
\begin{align}
res &= \frac{C_{col_1}^{2}}{C_{n}^{2}}+\frac{C_{col_2}^{2}}{C_{n}^{2}}+\dots+\frac{C_{col_k}^{2}}{C_{n}^{2}} \\
&=\frac{C_{col_1}^{2}+C_{col_2}^{2}+\dots+C_{col_k}^{2}}{C_{n}^{2}} \\
&= \frac{col_1(col_1 - 1) + col_2(col_2 - 1) + \dots + col_k(col_k - 1)}{n(n-1)} \\
\end{align}
$$
上面的式子是对于一个区间来说的答案，其中$n$为选取的个数，而$col$表示对于颜色的个数，一共有$k$个颜色。由于分母在每个区间的值是唯一的，所以在莫队扩展的时候只需要关注分子。

那么当我们需要将区间扩展的时候，可能存在两种情况，一个是某颜色增加或者某颜色的减少。
那么分子我们可以先减去原先的二项式再加上新的二项式，当然也可以这么优化：
- 对于增加的颜色，就是分子加上$(col[i] + 1)\times col[i] - col[i]\times (col[i] - 1) = 2col[i]$，也就是分子直接加上$2col[i]$，然再更新$col[i]$
- 对于减少的颜色，就是分子减去$col[i]\times (col[i] - 1) - (col[i] - 1) \times (col[i] - 2) = 2(col[i] - 1)$。也就是先更新$col[i]$，然后分子再减去$col[i]$。

# 普通莫队操作
由于莫队中定义了，必须在$O(1)$的时间复杂度内能够将区间往外扩张，所以这个是大前提。

莫队的操作很简单：
- 离线后排序，顺序处理每个询问，暴力从上一个区间的答案转移到下一个区间答案（一步一步移动即可）。

为了使从上一个区间的答案转移到下一个区间答案时不会超时，我们需要对区间查询先进行分块，再按照分的块进行排序。排序方法就是：对于区间 $[l,r]$，以 $l$ 所在块的编号为第一关键字，$r$ 为第二关键字从小到大排序。
```cpp
// BLOCK为块的大小
int n,m,BLOCK;
struct Querry {
	int l,r,id;
	bool operator<(const Querry& _) const {
		if (l / BLOCK != _.l / BLOCK) return l / BLOCK < _.l / BLOCK;
		else return r < _.r;
	}
}q[N];
signed main() {
	cin>>n>>m;
	BLOCK = sqrt(n);
	for (int i = 1;i <= n;++i) cin>>c[i];
	// 对每个查询分别输入
	for (int i = 1;i <= m;++i) {
		cin>>q[i].l>>q[i].r;
		q[i].id = i;
	}
	// 对查询排序
	sort(q + 1,q + 1 + m);
}
```

在排序结束后，我们就需要对每个查询进行求解（代码延续上面的）
```cpp
int sum;
int c[N],ans1[N],ans2[N],col[N];
// 添加颜色的时候
void add(int i) {
	// 先加上2col[i]
	sum += 2 * col[i];
	// 再更新
	col[i]++;
}
void del(int i) {
	// 先更新
	col[i]--;
	// 再减去2col[i]
	sum -= 2 * col[i];
}
signed main() {
	for (int i = 1,l = 1,r = 0;i <= m;++i) {
		// 在一个点内的时候，是肯定不可能存在有效的解的，直接输出概率为0的情况
		if (q[i].l == q[i].r) {
			ans1[q[i].id] = 0;
			ans2[q[i].id] = 1;
			continue;
		}
		// 这里四个区间更新的顺序千万不能乱，原因下面会提到
		
		// 左区间需要往外扩张，那么就先移动l，然后加上c[l]的值
		while(l > q[i].l) add(c[--l]);
		// 右区间需要往外扩张，那么就先移动r，然后加上c[r]的值
		while(r < q[i].r) add(c[++r]);
		// 左区间范围太大，需要缩小，那么就先减去c[l]的值，再移动l
		while(l < q[i].l) del(c[l++]);
		// 右区间范围太大，需要缩小，那么就先减去c[r]的值，再移动r
		while(r > q[i].r) del(c[r--]);
		
		int res1 = sum,res2 = (q[i].r - q[i].l + 1) * (q[i].r - q[i].l);
		// 约分操作
		int _ = __gcd(res1,res2);
		res1 /= _;
		res2 /= _;
		ans1[q[i].id] = res1;
		ans2[q[i].id] = res2;
	}
	for (int i = 1;i <= m;++i) cout<<ans1[i]<<'/'<<ans2[i]<<'\n';
	return 0;
}
```
时间复杂度为$O(n\sqrt n)$

## 关于四个循环位置
其实在刚开始学习莫队的时候，由于莫队中是包含$l$到$r$区间内的，那么刚开始初始化的时候设置$l = 1$而$r = 0$呢，原因之一是在于这个$l,r$没包含任何的元素，是和错误的集合。但是一想到给$l$初始化为$1$会不会出问题呢，倘若第一个查询是查找$l=2,r=n$位置的话，那么$l$在减的时候会不会多减第一个数字，也就是$i=1$时的位置。事实证明并不会。这个就关系到$l,r$的加减顺序了。

其实莫队区间的移动过程，就相当于加入了 $[1,r]$ 的元素，并删除了 $[1,l-1]$ 的元素，因此我们的$l,r$在移动的过程中，必须严格保证$l\le r + 1$一直成立。代码中的四个 `while` 循环一共有 $4!=24$ 种排列顺序。下表列出了这 12 种写法的正确性，还给出了错误写法的反例．

| 循环顺序              | 正确性 | 反例或注释       |
| ----------------- | --- | ----------- |
| `l--,l++,r--,r++` | 错误  | $l<r<l'<r'$ |
| `l--,l++,r++,r--` | 错误  | $l<r<l'<r'$ |
| `l--,r--,l++,r++` | 错误  | $l<r<l'<r'$ |
| `l--,r--,r++,l++` | 正确  | 证明较繁琐       |
| `l--,r++,l++,r--` | 正确  |             |
| `l--,r++,r--,l++` | 正确  |             |
| `l++,l--,r--,r++` | 错误  | $l<r<l'<r'$ |
| `l++,l--,r++,r--` | 错误  | $l<r<l'<r'$ |
| `l++,r++,l--,r--` | 错误  | $l<r<l'<r'$ |
| `l++,r++,r--,l--` | 错误  | $l<r<l'<r'$ |
| `l++,r--,l--,r++` | 错误  | $l<r<l'<r'$ |
| `l++,r--,r++,l--` | 错误  | $l<r<l'<r'$ |
全部 24 种排列中只有 6 种是正确的，其中有 2 种的证明较繁琐，这里只给出其中 4 种的证明．
这 4 种正确写法的共同特点是，前两步先扩大区间（`l--` 或 `r++`），后两步再缩小区间（`l++` 或 `r--`）．这样写，前两步是扩大区间，可以保持 $l\le r+1$；执行完前两步后，$l\le l'\le r'\le r$ 一定成立，再执行后两步只会把区间缩小到 $[l',r']$，依然有 $l\le r+1$，因此这样写是正确的．

## 时间复杂度分析
对于分块排序来说，复杂度为$O(n \log n)$。
接着就到了莫队算法的精髓了。
> [!note]- 证明
> 莫队的复杂度主要体现在指针的移动上，而我们存在左指针和右指针。
> 左指针存在同一个块内的移动和跨块之间的移动，那么对于左指针来说：
> - 如果是块内移动的话，那么左指针就是在块内移动，$m$次查询最多移动$m\times B$次，$B$为块长。
> - 如果是块间移动，由于已经按照块的大小排好序了，所以最多就只会移动$B$乘上块的个数$\frac{n}{B}$，也就是$n$次。
> 对于右指针来说：
> - 一个块最多就是从$1$到$n$，一共有$\frac{n}{B}$个块，最终会移动$\frac{n^2}{B}$次。
> 综上，时间复杂度为$O(mB+n+\frac{n^2}{B})$，显然$n$为常数，该函数是一个对勾函数，根据均值不等式$\frac{a+b}{2} \ge \sqrt {ab},a = b$时取最小值，得到时间最小时$mB = \frac{n^2}{B}$，$B=\frac{n}{\sqrt m}$时间最少，为$O(n\sqrt m)$。

所以莫队的理论时间复杂度为$O(n\sqrt n)$。
但是！
一定需要注意的是，在计算的过程中，我们省略了非常多的常数，导致莫队有**极大**的常数。是**极大**。一般来说足够支撑1e5的大小。

## 小优化
注意看我们下面的一个样例
```txt
// 设块的大小为 2 (假设)
1 1
2 100
3 1
4 100
```
在这个样例中，$r$移动的次数为$300$次，主要的浪费在于，一个块走完之后，在下一个块$r$需要从头开始，导致多走了一个$n$的时间复杂度，虽然是常数，但是也是一个时间浪费。为了防止这种情况的发生，我们采用奇偶排序的方式，也就是当块为奇数的时候$r$从小到大，当块为偶数的时候$r$从大到小，这样子优化，可以加速莫队$30\%$左右的时间。

那么我们对操作符进行重载的时候就可以这么修改
```cpp
struct node {
  int l, r, id;

  bool operator<(const node &x) const {
    if (l / unit != x.l / unit) return l < x.l;
    // 注意下面两行不能写小于（大于）等于，否则会出错
    if ((l / unit) & 1) return r < x.r;
    return r > x.r;
  }
};
```
