# 1.邻接矩阵(Adjacency Matrix)
## 存储方式：
使用二维数组`matrix[n][n]`，其中`matrix[u][v]`代表节点`u`到`v`的边权（无边时标记`INF`或者`0`）。

代码：

```cpp
#include <bits/stdc++.h>
#define ll long long
using namespace std;
const int INF = 0x3f3f3f3f;
const int N = 5010;//最大节点数量

//n为节点数量，m为边的数量
int n,m;

//初始化数组，matrix[u][v]代表u到v的边权
int matrix[N][N];
//vector<vector<int>> matrix(N,vector<int> (N,INF));//使用vector数组也可以

//via数组代表有没有读取到对应的节点k
bool via[N];

void solve() {
    //读入节点数量n和边的数量m
    cin>>n>>m;
    //设置每个节点到每个节点的距离为INF
    memset(matrix,INF,sizeof(matrix));
    //for循环表示节点从i到i的边权或者距离为0
    for (int i=1;i<=n;++i)matrix[i][i]=0;
    //读取节点和边权
    for (int i=0;i<m;++i){
        //x，y和z代表从x到y的边权为z
        int x,y,z;
        cin>>x>>y>>z;
        //如果已经存在从x到y的边，那存储最小值
        if (z<matrix[x][y]){
            //倘若时有向图，则不能这么写。应该是：
            //matrix[x][y] = z;
            matrix[x][y] = matrix[y][x] = z;
        }
    }

    for (int i=1;i<=n;++i){
        for (int j=1;j<=n;++j){
            if (matrix[i][j] != INF && i != j) {
                cout<<i<<" -> "<<j<<"的边权为"<<matrix[i][j]<<endl;
            }
        }
    }
}
int main() {
    ios::sync_with_stdio(0);
    cin.tie(0);
    cout.tie(0);
    ll t = 1;
    // cin>>t;
    while (t--)
    solve();
    return 0;
}
```

## 复杂度
+ 查询是否存在某条边：`O(1)`
+ 遍历一个点的所有边：`O(n)`
+ 遍历整张图：`O(n²)`
+ 空间复杂度：`O(n²)`

## 优缺点：
### 优点：
+ 查询边存在性：直接访问 `matrix[u][v]`，时间复杂度 `O(1)`。
+ 适合稠密图：当边数接近 `n²` 时，空间利用率高。
+ 易于实现：代码简单，适合快速修改边权。

### 缺点：
+ 空间复杂度高：`O(n²)`，无法处理大规模稀疏图（如 `n=1e5` 时内存爆炸）。
+ 遍历邻接节点效率低：需要遍历所有节点，即使实际邻接节点很少。

## 适用场景：
+ 节点数较小（`n ≤ 1e3`）。
+ 频繁查询边是否存在或修改边权。
+ 稠密图算法（如 Floyd-Warshall 全源最短路）。

# 2.邻接表 (Adjacency List)
## 存储方式：
使用 `vector<vector<pair<int, int>>> graph`，其中 `graph[u]` 存储所有从 `u` 出发的边，每条边以 `(v, w)` 形式表示目标节点和边权。

代码：

```cpp
#include <bits/stdc++.h>
#define ll long long
using namespace std;
const int INF = 0x3f3f3f3f;
const int N = 5010;//最大节点数量

//n为节点数量，m为边的数量
int n,m;

//初始化邻接表，其中graph[u]存储所有从u出发的边，每条边以(v,w)形式，v表示目标节点，w表示边权
vector<vector<pair<int,int>>> graph(N);

void solve() {
    cin>>n>>m;
    //读取节点和边权
    for (int i=0;i<m;++i){
        //x，y和z代表从x到y的边权为z
        int x,y,z;
        cin>>x>>y>>z;
        pair<int,int> temp1(y,z);
        pair<int,int> temp2(x,z);
        graph[x].push_back(temp1);
        graph[y].push_back(temp2);
    }
    for (int i=1;i<=n;++i){
        for (int j=0;j<graph[i].size();++j){
            cout<<i<<" -> "<<graph[i][j].first<<"的边权为"<<graph[i][j].second<<endl;
        }
    }
}
int main() {
    ios::sync_with_stdio(0);
    cin.tie(0);
    cout.tie(0);
    ll t = 1;
    // cin>>t;
    while (t--)
    solve();
    return 0;
}
```

## 复杂度
+ 查询是否存在u到v的边：$O(d^{+}(u))$ （如果事先进行了排序就可以使用二分查找做到$O(\log (d^{+}(u)))$ ）。
+ 遍历点u的所有出边：$O(d^{+}(u))$。
+ 遍历整张图：$O(n+m)$。
+ 空间复杂度：$O(m)$。

## 优缺点
### 优点
+ 空间效率高：空间复杂度 `O(n + m)`，适合稀疏图。
+ 快速遍历邻接节点：直接遍历 `graph[u]`，无需检查所有节点。
+ 动态扩展方便：适合动态添加边的场景。

### 缺点
+ 查询边存在性慢：需要遍历 `graph[u]` 查找 `v`，时间复杂度 `O(k)`（`k` 为 `u` 的邻接节点数）。
+ 缓存不友好：链表或 `vector` 存储可能导致随机访问性能下降。

## 适用场景
+ 稀疏图（如 `m ≈ n`）。
+ 需要频繁遍历邻接节点的算法（如 BFS、DFS、Dijkstra 堆优化）。

# 3. 边列表 (Edge List)
## 存储方式：
使用数组 `vector<Edge> edges` 存储所有边，每条边记录 `(u, v, w)`。(Edge为有u,v,w的类或者结构体)

代码：

```cpp
#include <bits/stdc++.h>
#define ll long long
using namespace std;
const int INF = 0x3f3f3f3f;
const int N = 5010;//最大节点数量

//n为节点数量，m为边的数量
int n,m;

//构造边列表,Edge里的u,v,w属性代表从u到v的边权为w
struct Edge{int u,v,w;};
vector<Edge> graph;

void solve() {
    cin>>n>>m;
    //读取节点和边权
    for (int i=0;i<m;++i){
        int x,y,z;
        cin>>x>>y>>z;
        Edge g1,g2;
        g1.u = x,g1.v = y,g1.w = z;
        g2.u = y,g2.v = x,g2.w = z;
        graph.push_back(g1);
        graph.push_back(g2);
    }
    for (int i=0;i<graph.size();++i){
        cout<<graph[i].u<<" -> "<<graph[i].v<<"的边权为"<<graph[i].w<<endl;
    }
}
int main() {
    ios::sync_with_stdio(0);
    cin.tie(0);
    cout.tie(0);
    ll t = 1;
    // cin>>t;
    while (t--)
    solve();
    return 0;
}
```

## 复杂度:
+ 查询是否存在某条边：`O(m)`。
+ 遍历一个点的所有出边：`O(m)`。
+ 遍历整张图：`O(nm)`。
+ 空间复杂度：`O(m)`。

## 优点和缺点
### 优点
+ 空间紧凑：仅存储有效边，空间复杂度 `O(m)`。
+ 适合按边遍历：方便处理所有边（如 Kruskal 算法需排序边）。
+ 简单通用：无需预分配内存，动态添加边灵活。

### 缺点
+ 查询邻接节点困难：需遍历整个列表，时间复杂度 `O(m)`。
+ 无法快速定位边：修改或删除边效率低。

## 适用场景
+ 需要全局处理所有边的算法（如 Kruskal 求[[最小生成树]]）。
+ 对节点邻接关系查询需求较少的场景。

# 4. 链式前向星 (Linked Forward Star)
## 存储方式
使用两个数组 `head[n]` 和 `edges[m]`，其中 `head[u]` 指向 `u` 的第一条边在 `edges` 中的索引，每条边记录 `(v, w, next)`，`next` 指向下一条边。

代码：

```cpp
#include <bits/stdc++.h>
#define ll long long
using namespace std;
const int INF = 0x3f3f3f3f;
const int MAX_M = 1e5+5;//最大边数量
const int N = 5010;//最大节点数量

//n为节点数量，m为边的数量，cnt为计数器，计数已经加入的边的数量
int n,m,cnt = 0;

//构造边列表,Edge里的v,w,next属性代表从u到v的边权为w,next存储的是新的u链表插入时候的上一条边对应在graph数组中的索引
struct Edge{int v,w,next;};
vector<Edge> graph(MAX_M*2);

//存储的是以节点u为末尾的边
int head[N];

//添加边的函数
void add_graph(int u,int v,int w){
    graph[cnt].v = v;
    graph[cnt].w = w;
    //插入边的上一条边的索引即用数组模拟链表
    graph[cnt].next = head[u];
    //更新链表的头节点
    head[u] = cnt++;
}
void solve() {
    cin>>n>>m;
    fill(head,head+N,-1);
    //读取节点和边权
    for (int i=0;i<m;++i){
        int x,y,z;
        cin>>x>>y>>z;
        add_graph(x,y,z);
        add_graph(y,x,z);
    }
    for (int i=1;i<=n;++i){
        int k = head[i];
        while(k!=-1){
            cout<<i<<" -> "<<graph[k].v<<"的边权为"<<graph[k].w<<endl;
            k = graph[k].next;
        }
    }   
}
int main() {
    ios::sync_with_stdio(0);
    cin.tie(0);
    cout.tie(0);
    ll t = 1;
    // cin>>t;
    while (t--)
    solve();
    return 0;
}
```

## 复杂度：
+ 查询是否存在u到v的边：`O(d+(u))`（如果事先进行了排序就可以使用二分查找做到`O(log(d+(u)))`）。
+ 遍历点u的所有出边：`O(d+(u))`。
+ 遍历整张图：`O(n+m)`。
+ 空间复杂度：`O(m)`。

## 优点和缺点
### 优点：
+ 内存连续：用数组模拟链表，缓存友好。
+ 空间高效：与邻接表相同，空间复杂度 `O(n + m)`。
+ 静态存储：适合预先知道边数的场景。

### 缺点：
+ 代码复杂：需要维护 `head` 和 `next` 指针，实现较繁琐。
+ 动态扩展不便：添加边需预先分配内存。

## 适用场景
+ 算法竞赛中处理大规模稀疏图（如 `n=1e5, m=2e5`）。
+ 需要高效遍历邻接节点的算法（如 SPFA 最短路）。

# 总结对比表
| **存储方式** | **空间复杂度** | **查询边存在性** | **遍历邻接节点** | **适用场景** |
| --- | --- | --- | --- | --- |
| 邻接矩阵 | O(n²) | O(1) | O(n) | 小规模稠密图 |
| 邻接表 | O(n + m) | O(k) | O(k) | 通用稀疏图 |
| 边列表 | O(m) | O(m) | O(m) | 需要全局处理边的算法 |
| 链式前向星 | O(n + m) | O(k) | O(k) | 算法竞赛中的大规模稀疏图 |
